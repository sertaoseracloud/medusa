<objective>
Stand up the hardened realtime gateway and the first live data source: an authenticated, topic-scoped WebSocket endpoint at `GET /realtime` that fans Binance miniTicker frames out only to the sockets that subscribed to that symbol's topic.

Purpose: this is the backend half of the "user sees a live ticker" slice. Every legacy WebSocket defect named in CONCERNS.md (token in URL, backwards CORS check, broadcast-to-all, no heartbeat, no disconnect cleanup) is fixed here, once, before any other topic is added on top.
Output: `bus/`, `realtime/`, `exchanges/binance/binance.stream.ts`, an extended `IExchangeAdapter`, and four automated test files proving auth, authorization, topic isolation and ticker normalization.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `GET /realtime` upgrade | Untrusted origin and untrusted first message cross here; no authentication exists until the handshake completes |
| authenticated socket → subscription registry | A client-chosen arbitrary topic string crosses here; private topics must be authorized server-side |
| Binance WS servers → `binance.stream.ts` | Untrusted/unavailable third-party input crosses here (malformed frames, abrupt closes) |
