<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → topic string | A persisted, user-controllable symbol value becomes part of a subscription topic sent to the server |
| third-party CDN (`s3.tradingview.com`) → page | External executable script crosses into the app's origin |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Tampering | `useSelectedSymbol` → topic construction | mitigate | Stored symbol is uppercased and falls back to `'BTCUSDT'` when absent/empty; the server independently validates every topic through `parseTopic` and bounds it to 128 chars (Plan 02-01), so a tampered localStorage value yields a rejected subscribe, never a malformed server state |
| T-02-12 | Tampering | TradingView `tv.js` third-party script | accept | Loaded from TradingView's own official CDN URL (never a mirror), rendered in an isolated container that receives no tokens, credentials or balance data; this is the same trust posture the legacy system already had and is inherent to the free embed (RT-03 requires it) |
| T-02-13 | Information Disclosure | chart widget context | mitigate | Only the public trading pair symbol is passed to the widget; no access token, user id, or account data is ever placed in the widget options or its container |
| T-02-SC | Tampering | npm installs | accept | Only official shadcn registry components (`popover`, `command`) are added; 02-UI-SPEC.md marks the official registry as requiring no safety gate, and no `[ASSUMED]`-provenance package is installed |
</threat_model>
