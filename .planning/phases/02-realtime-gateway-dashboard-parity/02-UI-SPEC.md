# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope covered by this contract:** the Dashboard screen (`frontend/src/private/Dashboard/index.tsx`) extended with a symbol-selection combobox (D-07/D-08), a live mini-ticker card, a 10-level depth order book panel (D-01/D-02), an all-assets balance table (D-03), a TradingView chart widget (RT-03), and a connection-status banner for WebSocket reconnection (D-04). This phase does **not** touch the login, settings, or symbol-sync screens already specified in `01-UI-SPEC.md` — it extends the same design system with live-data widgets on the dashboard only.

**Inheritance note:** This is not a new design system. `components.json`, `src/index.css` design tokens (spacing, typography roles, color variables), and the dark theme are already implemented in the repo from Phase 1 and are used as-is. No new tokens are introduced. Only new component inventory and copy specific to real-time widgets are declared below.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `frontend/components.json` present, confirmed via file read) |

**Components already present (reused, no changes):** `alert`, `badge`, `button`, `card`, `form`, `input`, `label`, `separator`.

**New components needed this phase (from shadcn official registry only):**
- `table` — order book (bid/ask 10-level depth) and balance panel (all assets, D-03)
- `popover` + `command` — symbol search-combobox (D-07)
- `skeleton` — loading placeholder for ticker/book/balance before first WebSocket message arrives
- `tooltip` — optional truncated-asset-name hints in the balance table (discretion: only if asset names are wider than column)
- `scroll-area` — vertical scroll container for the balance table (all assets, no min-balance filter per D-03, list can be long)

No third-party registries required. TradingView chart widget (RT-03) is embedded via the official TradingView widget script/iframe, not a shadcn component — it is a plain `<div>` container styled with existing card/spacing tokens, not part of the shadcn registry surface.

## Spacing Scale

Inherited from Phase 1 — no changes. Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (e.g., bid/ask row internal spacing) |
| sm | 8px | Compact element spacing (table cell padding, badge padding) |
| md | 16px | Default element spacing (between dashboard cards, card padding) |
| lg | 24px | Section padding (dashboard grid gutter between ticker/book/balance/chart cards) |
| xl | 32px | Layout gaps (page margins on desktop) |
| 2xl | 48px | Major section breaks (not heavily used on the dense dashboard grid) |
| 3xl | 64px | Page-level spacing (not used this phase) |

Exceptions: none. Reconnection banner (D-04) uses `sm` (8px) vertical padding to stay visually discreet/non-blocking per D-04's "discrete banner" requirement — it must not push page content down by more than one line height.

## Typography

Inherited from Phase 1 — no changes (exactly 2 weights, 4 sizes, already implemented as CSS utility classes `.text-role-*` in `src/index.css`).

| Role | Size | Weight | Line Height | Phase 2 usage |
|------|------|--------|-------------|----------------|
| Body | 16px | 400 (regular) | 1.5 | Ticker price, book price/quantity cells, balance amounts |
| Label | 14px | 600 (semibold) | 1.5 | Table column headers (Bid/Ask/Price/Qty, Asset/Available/Locked), badge text, symbol combobox placeholder |
| Heading | 20px | 600 (semibold) | 1.2 | Card titles ("Book de Ofertas", "Saldo", "Gráfico") |
| Display | 28px | 600 (semibold) | 1.2 | Live ticker last-price (the single most important number on the dashboard — largest visual weight) |

Numeric alignment: all price/quantity/balance figures use tabular/monospace numeric rendering (`font-variant-numeric: tabular-nums` utility) so columns align — required for the order book and balance table to be scannable, not a new type role.

## Color

Inherited from Phase 1 — no new hex values. Usage extended to real-time semantics:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0A0E14` | Dashboard page background |
| Secondary (30%) | `#151B26` | Ticker card, order book card, balance card, chart card, combobox popover background |
| Accent (10%) | `#3B82F6` | Symbol combobox selected state, active/focused row, "Reconectando..." banner icon only |
| Destructive | `#EF4444` | Reserved for hard connection-failure states only (see below) |

**New semantic colors required this phase (not in Phase 1, additive — must be added to `src/index.css` as new CSS variables, not ad-hoc hex in components):**

| Role | Value | Usage |
|------|-------|-------|
| Bid/buy (positive) | `#22C55E` (green-500) | Order book bid-side rows/depth bars, ticker price when last tick moved up |
| Ask/sell (negative) | `#EF4444` (reuse existing destructive red) | Order book ask-side rows/depth bars, ticker price when last tick moved down |
| Neutral/unchanged | `#94A3B8` (existing `--muted-foreground`) | Ticker price when unchanged since last tick |

Accent (`#3B82F6`) reserved for: symbol combobox trigger button, combobox selected-item highlight, focus rings — same reservation as Phase 1, extended to the new combobox. Accent must NOT be used for bid/ask coloring (that is bid/ask green/red semantic color, not brand accent) — this is the one new rule this phase adds to the color contract.

Destructive (`#EF4444`) reserved for: ask-side book rows (shared with bid/ask semantics above — acceptable overlap since red=sell is a universal trading convention) and the hard-failure state of the reconnection banner (see Copywriting below) after repeated reconnect attempts fail.

## Copywriting Contract

All copy in Portuguese, matching Phase 1 and project convention.

| Element | Copy |
|---------|------|
| Symbol combobox placeholder | "Selecionar par..." |
| Symbol combobox search placeholder | "Buscar símbolo (ex: BTCUSDT)" |
| Symbol combobox empty result | "Nenhum símbolo encontrado" |
| Dashboard loading skeleton (before first WS message) | (no text — skeleton shimmer only, per component convention) |
| Reconnection banner — soft (client WS dropped, D-04) | "Reconectando..." (discreet, non-blocking, last known values remain visible per D-04) |
| Reconnection banner — hard failure (repeated attempts exhausted) | "Conexão perdida. Os dados exibidos podem estar desatualizados. Tentando novamente..." (destructive-tinted, still non-modal — dashboard remains usable with stale data) |
| Order book empty/no-liquidity state | "Sem dados de profundidade no momento" |
| Balance panel empty state (should not normally occur since all assets shown per D-03, but covers zero-balance account) | "Nenhum ativo encontrado nesta conta" |
| Balance panel column headers | "Ativo" / "Disponível" / "Bloqueado" |
| Order book column headers | "Preço" / "Quantidade" (repeated under both Bid and Ask sub-headers "Compra" / "Venda") |
| TradingView chart loading state | "Carregando gráfico..." |
| TradingView chart load failure | "Não foi possível carregar o gráfico. Verifique sua conexão e recarregue a página." |
| Error — WebSocket handshake auth failure (SEC-06 — token rejected at first-message exchange) | "Sessão expirada. Faça login novamente." (redirect to login, mirrors Phase 1 401 handling) |
| Destructive confirmation | None this phase — no destructive user actions are introduced (symbol switching and reconnection are non-destructive, reversible state changes, not data-loss actions) |
