<!-- Backend HTTP contract from Plan 02. Use directly; do not re-derive from backend source. -->
POST /auth/login  body { email, password }
  200 → { data: { accessToken: string, refreshToken: string, tokenType: 'Bearer', expiresIn: 900, user: { id: string, email: string } }, message, timestamp }
  400 → { data: { fields: [{ field: string, message: string }] }, message: 'Validation failed', timestamp }
  401 → { data: null, message: 'Email ou senha incorretos.', timestamp }
  429 → { data: null, message: 'Muitas tentativas. Aguarde alguns minutos antes de tentar novamente.', timestamp }
GET /auth/me   header Authorization: Bearer <accessToken>
  200 → { data: { id: string, email: string }, message, timestamp }
  401 → { data: null, message, timestamp }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser origin → API | The frontend origin must be inside the backend's CORS allowlist; any other origin is untrusted |
| Browser storage → API requests | Tokens held in `localStorage` are readable by any script running on the origin |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SEC05f | Spoofing | Frontend origin vs. `CORS_ORIGINS` | mitigate | `VITE_API_URL` and the backend `CORS_ORIGINS` allowlist are configured as an explicit pair (`http://localhost:5173`); no wildcard origin is introduced on either side |
| T-01-XSSTOK | Information Disclosure | Access/refresh tokens in `localStorage` | accept | Single-operator, locally-run tool with no user-generated content rendered and no third-party script tags; React escapes interpolated values by default. Revisit if any HTML-rendering surface is added. Compensating control: the access token lives 15 minutes and the refresh token is revocable server-side (Plan 06) |
| T-01-ENUMf | Information Disclosure | Login error rendering | mitigate | The UI renders the server's single generic 401 message; it never branches on "unknown email" vs "wrong password" |
| T-01-SILENT | Repudiation | Hydration on a 401 | mitigate | A failed `GET /auth/me` during bootstrap clears stored tokens silently and returns the operator to `/login` (D-10) rather than leaving a stale authenticated shell rendered |
</threat_model>
