<!-- Backend HTTP contract from Plans 05 and 06 -->
GET /settings/credentials   auth required
  200 → { data: { exchangeId: 'binance', configured: boolean, accessKeyMasked: string | null, secretKeyMasked: string | null, updatedAt: string | null }, message, timestamp }
PUT /settings/credentials   auth required, body { accessKey: string, secretKey: string }
  200 → { data: SettingsDto, message, timestamp }
  400 → { data: null, message: '<invalid key OR missing permission message>', timestamp }   // discriminate via the error code below
  503 → { data: null, message: '<exchange unavailable message>', timestamp }
PATCH /auth/password        auth required, body { currentPassword, newPassword (min 12) }
  204 → no body | 401 → wrong current password | 400 → per-field Zod errors

Domain error codes surfaced by the backend (use the code, never string matching):
  EXCHANGE_AUTH | EXCHANGE_PERMISSION | EXCHANGE_UNAVAILABLE | EXCHANGE_UNKNOWN | INVALID_CREDENTIALS

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator keyboard → browser form | The plaintext Binance secret exists in the browser only between keystroke and request |
| Browser → backend settings API | The only destination the secret is ever transmitted to |
| Backend response → rendered DOM | Where the legacy system leaked the raw secret |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SEC07ui | Information Disclosure | Credentials card rendering | mitigate | Only the server-provided masked strings are rendered; no reveal toggle exists (blocked by an acceptance grep); the component test asserts the full fixture secret never appears in the DOM (fixes the legacy screen that displayed `secretKey` verbatim) |
| T-01-DIRECTEX | Information Disclosure | Any client-side exchange call | mitigate | The browser never calls Binance; credentials go only to `PUT /settings/credentials`, asserted by a grep for exchange hostnames in `frontend/src` |
| T-01-DBLSUBMIT | Denial of Service | Save button during the live exchange round trip | mitigate | The submit control is disabled for the whole request so one click cannot trigger multiple `fetchBalance` calls against Binance's rate limit |
| T-01-ERRCODE | Information Disclosure | Error rendering | mitigate | The UI branches on the backend's stable error `code` and renders only the four curated Portuguese strings; raw backend error text is never interpolated into the DOM |
| T-01-PWWARN | Repudiation | Password-change expectations | mitigate | The D-04 warning is permanently rendered above the form, and checkpoint step 8 verifies the stated revert behaviour actually matches reality |
| T-01-SECINPUT | Information Disclosure | Secret input field | mitigate | `type="password"` on the secret input keeps it out of shoulder-surfing range and out of browser autofill suggestions for plain text fields |
</threat_model>
